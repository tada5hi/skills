# update-agent-docs

> **Propose improvements to the init-agent-docs templates as a pull request to tada5hi/skills.**
> Stop letting the structure you refined in one project's agent docs stay in that project.

[All skills](../../README.md#skills) · [`SKILL.md`](./SKILL.md)

## Why update-agent-docs?

Agent docs generated by [init-agent-docs](../init-agent-docs/) get refined in each project: a new section, a clearer table, better guidance for the next agent. Without a way back, every project rediscovers the same improvements. Contributing them by hand means comparing six files against the templates and stripping out everything project-specific.

| Concern | Without it | With update-agent-docs |
|---|---|---|
| **Finding improvements** | Diff each project doc against its template by hand | Reads the project's docs and the templates side by side and sorts findings into new section, better structure, new placeholder, improved guidance and stale content |
| **Project details** | Real paths and package names leak into templates | Generalizes concrete content back to placeholders and HTML comment guidance |
| **Compatibility** | Templates change shape under other projects | Keeps existing placeholders and sections unless they are explicitly being improved |
| **Versioning** | Version left unchanged | Bumps `metadata.version` in the init-agent-docs `SKILL.md` to today's date |
| **The pull request** | A diff without context | A PR that names the project that surfaced the change and why it helps others |

## Installation

```bash
# this skill only, any Agent Skills agent
npx skills add tada5hi/skills --skill='update-agent-docs'

# Claude Code: the plugin bundles every skill
/plugin marketplace add tada5hi/skills
/plugin install skills@tada5hi
```

## Triggering

**Ask for it.** The agent loads the skill when your request matches its description, for example:

- "update the skill templates"
- "contribute back to skills"
- "improve the agent docs templates"

The agent may also use it when a project's agent docs have patterns worth upstreaming.

**Invoke it directly.** Type `/update-agent-docs` (installed with the skills CLI) or `/skills:update-agent-docs` (Claude Code plugin).

## What it does

1. Reads the project's `CLAUDE.md`, `AGENTS.md` and `.agents/*.md` next to the matching templates in `skills/init-agent-docs/templates/`.
2. Locates the skills repository: asks you, checks for a sibling `skills` directory, or clones `tada5hi/skills`.
3. Categorizes each difference and separates structural improvements from project-specific content.
4. Creates an `update-init-agent-docs-templates-<date>` branch, edits the templates (including `scripts/lint-agent-docs.mjs`), bumps the version in the init-agent-docs `SKILL.md`, and updates its placeholder and template tables and guidelines when the templates gain entries.
5. Commits as `feat(init-agent-docs): update templates`, pushes the branch and opens a pull request against `tada5hi/skills`.

## Requirements

- git.
- The `gh` CLI, authenticated with push access to `tada5hi/skills`; without it, the skill forks the repository and pushes to the fork.
- A project with agent docs in the init-agent-docs layout.

## Output

A pull request against `tada5hi/skills` with a summary, a list of changes and the motivation:

```markdown
## Summary

Template improvements based on real-world usage in `my-project`.
```

## Notes

- **Templates stay generic.** Real package names, URLs and file paths never go into a template.
- **One concern per PR.** Unrelated improvements are better as separate pull requests; related changes are bundled.
- **Only init-agent-docs changes.** It stages `skills/init-agent-docs/` and nothing else.
- **No AI attribution** in the commit message, PR title, body or comments.
